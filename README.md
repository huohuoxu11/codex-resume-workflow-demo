# 定向简历工作流 Demo

一个面向 AI 产品、产品运营与项目类岗位的作品展示：将“理解岗位—匹配可证明经历—组织业务表达—进行真实性审计”拆解为可观察的交互流程。项目用于展示使用 Codex 进行工作流设计、前端原型交付和质量控制的能力；它不是线上简历生成 SaaS，也不宣称具备未实现的模型推理能力。

## 项目背景与用户痛点

求职者为多个岗位制作简历时，常遇到三类问题：

1. **岗位理解停留在关键词层面**：同一份经历被机械复制，无法回应岗位真正的业务场景。
2. **表达难以兼顾专业性与可信度**：堆叠指标、工具和术语，反而让招聘方难以判断候选人的实际职责边界。
3. **产出缺乏质量控制**：未经确认的技能、项目或结果容易进入简历，影响面试可追问性。

本 Demo 把以上问题转为一条可检查的工作流，强调“业务问题 → 分析判断 → 支持动作/交付”，并将真实性边界显式呈现。

## 产品功能与运行状态

| 功能 | 当前状态 | 说明 |
| --- | --- | --- |
| 演示场景切换 | 已实现 | 可切换 AI 产品/项目助理、海外产品运营、商业化广告策略运营三套脱敏预设。 |
| JD 文本编辑 | 已实现 | 文本可直接编辑，仅在浏览器内存中处理。 |
| 本地规则匹配 | 已实现 | 点击运行后，根据输入中的岗位关键词，将页面匹配到三类预设演示模板之一。 |
| 工作流状态呈现 | 已实现 | 四个步骤以可视化状态依次展示。 |
| 结果预览与招呼语复制 | 已实现 | 预览随匹配模板切换；复制按钮在 HTTPS 或受信任本地环境调用浏览器 Clipboard API，若权限受限会明确提示手动复制。 |
| 真实性审计清单 | 已实现 | 以固定检查项展示人工复核应关注的边界。 |
| 任意 JD 的语义理解与定制生成 | 未实现 | 当前没有大模型、向量检索或后端生成服务，不能根据任意 JD 产出新的完整简历。 |
| 真实经历库读取、简历导出、账号系统 | 未实现 | 页面不读取本地简历，不生成 PDF，不保存用户数据。 |

## 工作流逻辑

1. **输入岗位信息**：选择预设场景或编辑 JD 摘要。
2. **识别业务方向**：前端用透明、可读的关键词规则将文本映射到 AI 产品、海外运营或商业化广告方向。
3. **展示经历重构原则**：对应模板说明哪些事实可以作为证据、如何按业务逻辑组织表达，以及哪些内容不能越界表述。
4. **执行质量审计**：展示岗位场景、事实边界、专业术语、三点匹配概览等审计项，提示真实交付中的人工复核重点。

## 技术实现

- **前端**：原生 HTML、CSS 与 JavaScript，零依赖、单页静态部署。
- **交互**：DOM 事件、预设数据对象、关键词正则分类、定时状态动画、Clipboard API。
- **隐私设计**：无后端、无数据库、无分析 SDK、无第三方网络请求；JD 编辑内容不离开当前浏览器页面。
- **部署方式**：适合 GitHub Pages、Netlify 或任意静态文件服务。GitHub Pages 无法提供模型推理能力，但足以承载本 Demo 的现有静态交互。

## 本地运行

直接在浏览器打开 `index.html`，或在目录中启动静态服务：

```bash
python3 -m http.server 8000
```

再访问 `http://localhost:8000`。

## GitHub Pages 部署

项目可直接作为静态站点部署，无需构建命令或服务器。

1. 在 GitHub 创建一个**公开**仓库，例如 `codex-resume-workflow-demo`。
2. 将本目录中的 `index.html`、`README.md` 与 `.gitignore` 推送到仓库默认分支。
3. 在仓库中进入 **Settings → Pages**，将 **Build and deployment** 设为 **Deploy from a branch**，选择默认分支的 `/(root)` 目录并保存。
4. GitHub 显示部署完成后，访问 `https://<GitHub用户名>.github.io/<仓库名>/`。

部署后的页面为 HTTPS，可使用浏览器 Clipboard API；公开前请再次确认仓库中只包含本目录的脱敏文件。

## 安全、数据与演示边界

- 页面只含脱敏示例；不含姓名、联系方式、原始简历、原始 JD 或 API 密钥。
- 不上传或持久化用户输入；刷新页面后编辑内容会丢失。
- 本地规则匹配是演示功能，不能描述为实时 LLM 推理或自动生成完整简历。
- 真实投递材料必须以用户确认的经历为依据，并由本人复核后再使用。

## 面向招聘方的项目亮点

- 将模糊的内容生产需求抽象为可验证的产品工作流与状态界面；
- 在产品表达中保留能力边界，避免用“AI”包装未落地能力；
- 用轻量前端将流程、风险与质量标准可视化，方便讨论后续如何接入真实经历库、结构化 JD 解析与人工审核节点。
